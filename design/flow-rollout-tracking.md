# 换版追踪模块：功能与用户流程

状态：**已定稿**（第 2 步 · 换版追踪，2026-11-03；6 个判断已定，见文末）
对应旅程：时刻 4「看板上出现一个红格：某班还没交回旧版」，以及阶段 6 收尾（design/journey-scenario1.md）

## 目的

连带文件的新版批准后，按文件组把「发新版、收旧版」落实到每个持有部门，让 QA 一眼看出哪个部门还没换、旧版有没有交回，最后为 QA 负责人签字关闭提供依据。

**使用者：** QA 文件管理员（主角）；部门持有人（触点：班组长、QC 主管）；QA 负责人（触点：收尾时看总览）。

**定位（来自产品定义）：** 系统里的「已发放」「已回收」只是**跟踪状态，不是 GMP 记录**。正式记录是纸质签收单：系统生成签收单，签回后由 QA 在系统里核销。

## 页面清单（共 6 个）

| # | 页面 | 它要回答的问题 | 主要动作 |
| --- | --- | --- | --- |
| 1 | 换版准备 | 这次变更要换哪些文件组？新版批准了吗？ | 查看每组的批准情况；（演示）标记新版已批准，生成任务 |
| 2 | 换版看板（部门 × 文件组） | 哪个部门还没换？旧版有没有交回？ | 一眼看全局；点格子看详情；催办 |
| 3 | 单个部门的任务 | 这个部门要领几份新版、交回几份旧版？到哪一步了？ | 部门持有人确认收到、交回；QA 代为登记 |
| 4 | 签收单 | 打印给部门签字的那张纸长什么样？ | 生成、打印签收单 |
| 5 | 签收单核销 | 签回来的纸和系统对得上吗？ | 输入或扫签收单编号，逐项核对，核销；处理不一致 |
| 6 | 变更收尾 | 能不能关闭这个变更？依据是什么？ | 查看换版和培训是否都完成；打印收尾总览 |

页面 6 是三个后段模块的汇合点：换版追踪 + 培训包都完成，变更才显示「可关闭」。

页面 3 和页面 5 有 A、B 两个版本（见下文「要比较的两个版本」）。

## 主流程

**QA：**
1. 影响清单导出后，进入换版准备，看到这次变更要换的文件组。新版的审批在 OA 里走，系统只读到「已批准」。**演示里由用户逐组标记「新版已批准」。**
2. 每批准一组，系统按台账的持有记录生成换版任务：每个「部门 × 文件组」一格，写明应发新版几份、应收旧版几份，以及上次换版遗留未交回的。
3. QA 按部门生成并打印签收单，随新版副本一起发下去。

**部门持有人：**
4. 收到新版，交回旧版，在纸质签收单上签字。可以在系统里点「已收到 / 已交回」，这只是跟踪状态。

**QA：**
5. 收回签了字的签收单，在系统里核销：核对份数和副本编号，对得上就核销，格子变成完成。
6. 看板上一眼看到还没完成的格子，尤其是红格（超期未回收、遗留旧版），去找对应的人。
7. 所有任务核销、培训也完成后，变更显示「可关闭」。QA 负责人据此在纸质变更控制单上签字。「可关闭」只是提示。

## 要比较的两个版本：换版确认方式

数据模型里「确认方式」字段两种都支持，界面原定第 5 周再定（决定记录 Q2）。现在两版都做，用户测试时比较。

- **A · QA 凭签收单核销（主线）：** 部门持有人收新交旧、在纸质签收单上签字，可以在系统里点「已收到 / 已交回」，但这一步可选。QA 收回签收单后在系统里逐项核销。签收单上的二维码只作示意。
  - 适合：车间没有电脑、不方便用手机的情况；纸面始终是唯一的依据。
  - 代价：系统状态要等签收单回来才更新，看板会慢半拍。
- **B · 部门扫码确认：** 签收单上印二维码。部门持有人用手机扫码，打开本部门这次的任务页，逐项点「已收到新版」「已交回旧版」，系统状态实时更新。QA 收到签回的纸质签收单后仍要核销，纸面仍是记录。
  - 适合：要实时看到进度的情况。
  - 代价：部门多一个动作（扫码 + 纸签），正是产品定义里列出的「双重动作」风险；乳膏车间的暴露工序在 D 级洁净区，能不能带手机进去扫码，文档没写，要验证。
- **原型里怎么做：** B 版要多做一个手机尺寸的任务页（项目的最小适配是 1366×768，这一页是例外），扫码用点击模拟。两版用一个隐藏开关切换，数据和逻辑共用。
- **怎么测：** 让部门持有人和 QA 完成同样的任务（例如「乙班领新版、交回旧版，QA 核销」），比较：部门愿不愿意多一个动作、QA 核销要花多久、看板是否及时、车间实际能不能用。

## 状态流转（来自数据模型）

- **换版任务：** 待发放 → 已发放 → 已回收 → 已核销
- **签收单：** 已生成 → 已打印 → 已签回 → 已核销

看板上每一格的颜色由任务状态决定；**系统里的状态和纸面是否核销要分开表达**，比如「部门说已交回，但签收单还没回来」。

## 关键状态

| 状态 | 在哪些页面出现 | 界面要表达什么 |
| --- | --- | --- |
| 还没有组获批（空状态） | 换版准备、看板 | 说明要等新版在 OA 批准，演示里可以点「标记已批准」 |
| 部分组获批 | 换版准备、看板 | 已批准的有任务，未批准的灰显 |
| 待发放 / 已发放 / 已回收 / 已核销 | 看板、部门任务 | 一眼分清四个阶段 |
| **超期未回收**（红） | 看板、部门任务 | 哪个部门、哪份、超期几天、找谁 |
| **遗留旧版未交回**（红） | 看板、部门任务 | 写明「上次换版遗留：01 版，乙班称已销毁，未见签收单」 |
| 部门说已交回，签收单未回 | 看板、核销 | 区分「跟踪状态」和「纸面已核销」 |
| 签收单与系统不一致 | 核销 | 例如份数不符，要求写明处理方式才能核销 |
| 某部门不持有任何受影响文件 | 看板 | 不出现在看板上，或灰显 |
| 全部核销 | 看板、收尾 | 换版完成；如果培训还没完成，说明还差什么 |
| 可关闭 | 收尾 | 明确「这只是提示，关闭由 QA 负责人签字」 |

## 已定的六个判断

1. **新版批准的演示：** 换版准备页上逐组「标记新版已批准（演示）」，演出连带文件陆续批准、看板一格一格亮起来。
2. **换版范围：** 按影响清单的人定档位预填。「必须改」的组换版，「需评估」的组由 QA 逐组选，「仅告知」的不换版，都可以改。源文件所在组一定换版。
3. **换版确认方式：** A、B 两版都做，用户测试时比较（见上文「要比较的两个版本」）。
4. **超期：** 新版生效之后旧版还没回收就算超期，标红。看板顶部有「演示日期」，可以往后推几天，看红格怎么出现。上次换版遗留的那一份，一开始就是红的。
5. **空白记录份数：** 原型只追踪受控副本，不显示空白记录份数。原型说明里写明这是样本的局限，不编数字。
6. **看板的形态**（谁作行谁作列；热力矩阵、任务列表还是班组卡片）留到第 3 步比较线框。
